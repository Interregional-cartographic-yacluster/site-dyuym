# Медиашкола «ДЮйМ»

Сайт медиашколы Центра детского творчества Курска: главная страница, архивы журналов и страницы проектов МХ «КРЯК» и «МЕДИАЗАВРЫ, вперёд!». Сайт статический, для подготовки страниц достаточно Python 3; установка зависимостей не требуется.

## Локальный запуск

Из корня репозитория запустите сервер предпросмотра:

```sh
python3 tools/preview_site.py --port 8000
```

Откройте `http://127.0.0.1:8000/главная`. Сервер сначала собирает временную копию сайта и поддерживает адреса без `.html` так же, как GitHub Pages. После изменения файлов перезапустите его. Обычный `python3 -m http.server` не разрешает такие адреса, а прямое открытие HTML-файла не подходит из-за ссылок от корня сайта.

Карта адреса на главной странице загружается с Яндекс Карт и требует интернета; если она недоступна, остаётся текстовый адрес. На странице КРЯКа интерактивная карта мира, России и Беларуси работает с локальными данными и требует JavaScript; её текстовые списки и переключатели доступны с клавиатуры. Встроенное видео «Медиазавров» загружается с VK и требует интернета, рядом есть прямая ссылка.

## Структура

- `index.html` — главная страница и меню «Главная», «Наши журналы» и «Проекты». В меню журналов доступны «Светлячок», вложенный в «Медиасобытия» «Волга-ЮНПРЕСС», Media Camp, «48-ая волна» и «Глобус». На телефоне навигация раскрывается кнопкой; без JavaScript меню остаётся доступным.
- `journals/` — пять страниц журналов, общее оформление и поиск по архиву «Светлячка». Сами выпуски и ссылки на них доступны и без JavaScript; просмотр по годам и поиск включаются с JavaScript. PDF открываются в Облаке Mail, остальные выпуски — на Calaméo.
- `projects/kryak.html` и `projects/mediazavry.html` — две страницы проектов по предоставленным исходным материалам; меню и светлый подвал совпадают с главной страницей.
- `projects/kryak.css`, `projects/mediazavry.css`, `projects/project-common.css` — оформление страниц проектов, общие карточки участников и адаптивные дополнения.
- `projects/kryak.js` — данные и управление интерактивной картой, а также подтверждение перехода к партнёрам. При отключённом JavaScript ссылки на партнёров остаются доступными.
- `styles.css` — оформление главной страницы, общего меню и подвала; максимальная ширина внешних блоков на всех страницах совпадает с навигацией.
- `script.js` — управление мобильной кнопкой меню и закрытие выпадающих разделов по Escape, при нажатии вне меню и при переходе по ссылке; сами разделы раскрываются и без JavaScript.
- `tools/site_routes.py` — соответствие публичных адресов и исходных HTML-файлов; `tools/build_site.py` создаёт копии страниц для этих адресов в артефакте `_site/`.
- `tools/preview_site.py` — локальный сервер с поддержкой адресов без `.html`.
- `.github/workflows/pages.yml` — проверка и публикация подготовленного артефакта через GitHub Actions.
- `CNAME` — имя домена; `.nojekyll` включается в подготовленный сайт.
- `assets/` — изображения, оптимизированные обложки выпусков в `assets/journal-covers/`, шрифты, иконки и их лицензии.

Проверить ссылки навигации, текст подвала, ресурсы и подготовленный артефакт можно командой:

```sh
python3 -m unittest discover -s tests
```

## Адреса страниц

В меню используются адреса без расширения `.html`:

| Страница | Путь |
| --- | --- |
| Главная | `/главная` |
| Светлячок | `/светлячок` |
| Волга-ЮНПРЕСС | `/медиасобытия/волга-юнпресс` |
| Media Camp | `/media-camp` |
| 48-ая волна | `/48-ая-волна` |
| Глобус | `/глобус` |
| МХ «КРЯК» | `/проекты/мх-кряк` |
| «МЕДИАЗАВРЫ, вперёд!» | `/проекты/медиазавры-вперёд` |

Кириллица в адресной строке и её запись с `%D0…` обозначают один и тот же адрес. GitHub Pages отдаёт файл `имя.html` и по адресу `/имя`; сборка создаёт такие файлы для всех путей. Ссылки в меню и канонические адреса ведут на новые пути. Корневой адрес `/`, прежний `/index.html` и старые адреса `projects/*.html` остаются доступны для закладок; автоматического перенаправления с них нет.

Для ручной подготовки артефакта выполните `python3 tools/build_site.py`: результат появится в `_site/`. Папка `_site/` при повторной сборке пересоздаётся. Публикация исходных файлов напрямую без сборки не создаст новые адреса.

## Публикация на GitHub Pages

Workflow `.github/workflows/pages.yml` проверяет сайт при отправке изменений в любую ветку и при pull request в `main`. Публикация выполняется только после успешной проверки изменений в `main`; запуски из рабочих веток не меняют опубликованный сайт. После объединения рабочей ветки с `main` сайт будет автоматически публиковаться при каждом обновлении `main`. Запустить workflow вручную из `main` можно на вкладке **Actions**.

Для подключения домена:

1. В настройках организации GitHub в разделе **Pages** рекомендуется подтвердить владение доменом `cdtkursk-dyuym.ru`, добавив предложенную GitHub TXT-запись в DNS. Это защитит домен и его поддомены от захвата. Подробности — в [документации GitHub](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/verifying-your-custom-domain-for-github-pages).
2. В настройках репозитория **Settings → Pages** выберите **Source → GitHub Actions**. В поле **Custom domain** укажите `www.cdtkursk-dyuym.ru` и сохраните. При публикации через Actions файл `CNAME` не подключает домен автоматически: настройка в GitHub обязательна. Домен необходимо добавить в GitHub Pages **до изменения DNS**.
3. В панели REG.RU откройте домен → **DNS-серверы и управление зоной → Изменить**. Удалите существующие A/AAAA-записи для `www`, если они есть, и добавьте запись:

   | Тип | Поддомен | Каноническое имя |
   | --- | --- | --- |
   | CNAME | `www` | `interregional-cartographic-yacluster.github.io` |

   Имя указывается без `https://` и без пути к репозиторию. Другие DNS-записи, в том числе MX и TXT, менять не нужно. [Инструкция REG.RU по настройке записей](https://help.reg.ru/support/dns-servery-i-nastroyka-zony/nastroyka-resursnykh-zapisey-dns/nastroyka-resursnykh-zapisey-v-lichnom-kabinete).
4. После обновления DNS дождитесь выпуска сертификата и включите **Enforce HTTPS** в настройках Pages, когда переключатель станет доступен. Проверяйте именно `https://www.cdtkursk-dyuym.ru/`.

Адрес без `www` не перенастраивается описанными действиями. Если он тоже должен открывать сайт, отдельно замените его A-запись на четыре адреса GitHub Pages: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`. При корректных записях для обоих имён GitHub Pages перенаправит домен без `www` на основной адрес с `www`. Не удаляйте другие типы записей домена. Подробности — в [документации GitHub](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site).

## Старый сайт на Google Сайтах

Google Сайты не позволяют настроить обычное серверное перенаправление с адреса `sites.google.com`. После запуска нового домена владелец старого сайта может открыть редактор и выбрать **Настройки → Баннер с уведомлением → Показать баннер**. Текст баннера: **«Мы переехали на новый сайт»**; надпись на кнопке: **«Перейти на новый сайт»**; ссылка: `https://www.cdtkursk-dyuym.ru/главная`. Затем нужно нажать **Опубликовать**. Это ссылка, требующая нажатия, а не автоматический редирект. [Инструкция Google](https://support.google.com/sites/answer/9826219?hl=ru).
